# Запуск на сервере

Пошагово: от пустого VPS до работающего сайта на своём домене.
Прежний сайт на Cloudflare всё это время продолжает работать — переключение
происходит в самом конце, одной сменой записи DNS.

## 1. Сервер

Подойдёт самый скромный: 2 ядра, 2 ГБ памяти, 20 ГБ диска. Нужны Docker
и плагин compose.

```bash
curl -fsSL https://get.docker.com | sh
```

Отдельный пользователь вместо root — чтобы случайная ошибка в контейнере
не стала ошибкой на всём сервере:

```bash
adduser --disabled-password --gecos "" tver
usermod -aG docker tver
```

## 2. Код и настройки

```bash
git clone https://github.com/lerowegr/tver-ryadom.git
cd tver-ryadom/backend
cp .env.example .env
```

В `.env` обязательно заполнить:

| Переменная | Чем заполнить |
|---|---|
| `ENVIRONMENT` | `production` |
| `JWT_SECRET` | `openssl rand -hex 32` — **не оставлять отладочный** |
| `POSTGRES_PASSWORD` | длинный случайный |
| `CORS_ORIGINS` | адреса сайта и админки через запятую |
| `SITE_URL` | `https://tver-ryadom.ru` |
| `R2_*` | доступы к хранилищу фотографий |

Приложение проверяет это само: с отладочным `JWT_SECRET` или пустым
`CORS_ORIGINS` в режиме `production` оно не стартует, а скажет, чего не
хватает. Лучше упасть на запуске, чем выдать токены, подписанные
общеизвестным секретом.

## 3. Первый запуск

```bash
docker compose up -d --build
docker compose logs -f api
```

Миграции накатываются при старте — отдельный ручной шаг рано или поздно
забывают, и прод уезжает от схемы.

Проверка: `curl http://127.0.0.1:8000/health` должен ответить
`{"success":true,...}`.

Наружу торчит только обратный прокси. Порт PostgreSQL не публикуется
намеренно: открытая наружу база — самый частый способ её потерять.

## 4. Перенос данных

Выгружаем из D1 и заливаем в PostgreSQL:

```bash
# на машине, где есть wrangler
pnpm --filter @tver/api exec wrangler d1 export tver-ryadom --remote --output dump.sql

# на сервере
docker compose cp dump.sql api:/tmp/dump.sql
docker compose exec api python scripts/migrate_from_d1.py /tmp/dump.sql --dry-run
docker compose exec api python scripts/migrate_from_d1.py /tmp/dump.sql
```

Сперва `--dry-run`: он ничего не пишет, только считает записи по таблицам.
Числа стоит сверить с тем, что показывает админка на старом сайте.

**Пароли переносятся как есть.** Хеши считались PBKDF2-SHA256 на 100 000
итераций, и Python воспроизводит их байт в байт — заводить пароль заново
никому не придётся. Это проверено до того, как была написана первая
строка остального кода.

Фотографии переносить не нужно: они остаются в том же R2.

## 5. Прокси и сертификат

Caddy получает сертификат сам и не требует настройки обновления:

```caddyfile
tver-ryadom.ru {
    # Картинки гоняются через приложение только если их не закэшировать.
    @images path /images/*
    header @images Cache-Control "public, max-age=31536000, immutable"

    reverse_proxy /api/* 127.0.0.1:8000
    reverse_proxy /images/* 127.0.0.1:8000
    reverse_proxy /calendar/* 127.0.0.1:8000
    reverse_proxy /webhook/* 127.0.0.1:8000
    reverse_proxy 127.0.0.1:3000
}
```

Фронтенд (Next.js) поднимается рядом тем же compose — вы выбрали вариант
«всё на одном сервере».

## 6. Боты и каналы

После того как домен заработал:

1. Админка → Настройки → **Подключить Telegram**. Кнопка сама
   зарегистрирует вебхук, заполнит меню команд и кнопку мини-приложения.
   Токен при этом не покидает сервер.
2. ВКонтакте: Callback API сообщества → адрес
   `https://tver-ryadom.ru/webhook/vk`, строку подтверждения и секрет
   вписать в `.env`.
3. MAX: нужен адрес API мессенджера — пока он не задан, канал принимает
   события, но не отвечает.

## 7. Переключение

Когда всё проверено на временном домене — меняете запись DNS на адрес
сервера. Старый сайт на Cloudflare остаётся работающим: если что-то
пойдёт не так, возврат — это та же запись обратно.

## Обслуживание

**Бэкап базы** — то, о чём вспоминают поздно:

```bash
docker compose exec -T db pg_dump -U tver tver | gzip > backup-$(date +%F).sql.gz
```

Поставьте это в cron и держите копию **не на том же сервере**.

**Обновление:**

```bash
git pull && docker compose up -d --build
```

**Сколько процессов.** По умолчанию один. Этого хватает: приложение
ждёт базу и сеть, а не считает. Если запустите несколько, помните: очередь
доставки к этому готова (задачи берутся с блокировкой строки), а счётчики
ограничения частоты живут в памяти процесса — предел станет во столько же
раз мягче.
